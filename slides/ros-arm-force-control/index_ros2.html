なぜ力制御が必要なのか？

全画面表示

  • 位置制御は「高さ」を守る
    → 1 mm 程度のずれ・凹凸で力が数倍、逆なら離れる
  • 硬いワークほど、わずかなずれで力が急増
  • 力制御は「押す力」を守る
    → ずれ・凹凸に倣って一定の力
  • 研磨・嵌合・人との協調作業に必要

受動コンプライアンス制御

  • アームは位置制御のまま
  • 手先にばね・ゲル等を挟んで柔らかくする
  • 機械要素なので力に即座に応答
  • 柔らかさは設計時に決まり、作業ごとに固定
  • 例: RCC による穴への軸の挿入

能動コンプライアンス制御

  • センサで力を測りサーボで柔らかく動く
  • 一般に「力制御」と呼ばれるのはこちら
  • 直接的: 力そのものを目標値に制御（ハイブリッド制御）
  • 間接的: 力と動きの関係を制御（インピーダンス制御）
  • 柔軟に変更できる反面、周期・安定性の制約あり

能動コンプライアンス 3方式の比較

インピーダンス制御 アドミッタンス制御 ハイブリッド位置/力制御

  • 受動コンプライアンスで事足りる作業も多い

力制御全般

力制御に必要なハードウェア

A. 位置制御ロボット ＋ 手先FTセンサ
（UR、一般の産業用ロボット）
  • 必要：手先の6軸力覚センサ
  • できる：アドミッタンス制御
    （位置制御主体＋手先FTセンサ向けの方法）
  • できない：インピーダンス制御
    （トルクを直接出せない）
  • 関節電流から力を推定する機種も
    （精度はロボット次第）
B. トルク制御ロボット
（Franka、KUKA iiwa）
  • 必要：関節トルクセンサ（内蔵）
  • できる：インピーダンスもアドミッタンスも
  • 柔らかく動かすならインピーダンスが自然
    （例：FR3 の
    cartesian_impedance_controller
    → 手先FTセンサなしで柔らかくできる）
  • 関節空間 → トルクをそのまま使う
  • 直交空間 → 手先の力に変換
    （F = J−Tτ）

関節トルクを出せるかどうかで、使える力制御が大きく変わる

力制御は制御周波数が効く

  • 能動制御は「測る → 計算 → 指令」を 1 周期ごとに繰り返す。周期の間は前の指令のまま
  • 硬い物ほど、その間に力が一気に変わる → 行き過ぎて振動・跳ね返り
  • 安定に出せる硬さは周期におおよそ反比例（K < 2b/T、Colgate & Schenkel 1997）

何 Hz あればいい？（目安）

位置制御100〜125 Hz人の動き（〜10 Hz）より十分速ければよい
やわらかい接触125〜500 Hzならい・フリードライブ。産業用ロボットの 125 Hz でも動く
硬い物・研磨500 Hz〜1 kHz硬いほど速い周期が必要（前のスライド）
力触覚伝送最低 1 kHz人が感じる帯域（〜1 kHz）を伝える。遅いと細かい感触が消える

インピーダンス制御

インピーダンス制御とは

  • 仮想的なスプリング・ダンパー・質量システムを実現
  • 目標位置と現在位置の差から力を計算
  • 接触力を制限して安全な作業が可能

インピーダンス制御の数式

F = Mẍ + Dẋ + K(x - x_d)

  • F: 発生する力
  • M: 仮想慣性
  • D: 仮想粘性
  • K: 仮想弾性
  • x - x_d: 位置誤差

手先の力 ⇔ 関節トルク：ヤコビアン

全画面表示

τ = JT F　　F = J−T τ

  • インピーダンス制御は手先で力 F を計算 → τ = JT F で関節トルクにしてモータへ
  • 関節トルクセンサから手先の力を知るときは逆向き（F = J−T τ）
  • J は「関節速度 → 手先速度」と同じ行列。姿勢で変わる
  • 腕が伸びきる（特異姿勢）と J−T が求まらない

インピーダンスパラメータの調整

  • K：硬さ（押されたときの逃げにくさ）　D：揺れの止まりやすさ　M：重さ（動き出しの遅さ）
  • 作業に合わせて調整（例：人と協調 → K 小・D 大、位置決め → K 大）

アドミッタンス制御

アドミッタンス制御とは

アプリ全画面

  • インピーダンス制御の逆
    • 力入力 → 位置出力
    • 人間の手動誘導に適している
  • メリット
    • 直感的な操作が可能
    • 安全性が高い

アドミッタンス制御の数式

M ac + D (vc − vd) + K (xc − xd) = F

  • F：FTセンサで測った外力（入力）
  • xc：計算した手先の位置指令（出力）。vc, ac はその速度・加速度（vd は目標の速度）
  • xd：本来の目標位置（軌道）
  • M / D / K：仮想の重さ / ダンパ / ばね（自分で決める）
  1. F を測る
  2. ac = M−1 [F − D(vc − vd) − K(xc − xd)]
  3. 積分して vc, xc を更新
  4. xc を位置制御に渡す（制御周期ごとに繰り返す）

力が 0 なら xc → xd（ふつうの位置制御と同じ）

コラム2つの制御則の中身

admittance_controller
（ros2_controllers）
  • M·a + D·v + K·x = F を実時間のまま積分
  • D = 2ζ(MK)1/2 = 200 N·s/m
    （M = 5 kg, K = 500 N/m, ζ = 2）
    → 0.1 m/s で動かすだけで約 20 N
  • 力は強い平滑化（係数 0.005）
    → 遅れ 約 0.4 s、離しても押され続ける
cartesian_compliance_controller
（FZI）
  • 正味の力 ＝ K·(目標 − 現在) ＋ 計測力
  • ほぼ質量の無い仮想ロボットに加え、
    順動力学で関節の動きを求める
  • 仮想時間は実時間の約10倍速
    → 概算 D ≈ 20 N·s/m、立ち上がり約 20 ms
  • 力は 20 Hz ローパスだけ → 遅れは数 ms

コラム押して離したときの動き

  • admittance を軽くするなら：damping_ratio を 0.7〜1 に（D = 70〜100 N·s/m）、filter_coefficient を 0.05 程度に（時定数 約 40 ms）
    ただし D を下げすぎると、硬い物に触れたとき振動・不安定になりやすい

※ admittance は設定値どおりの式で計算。FZI は手先質量 1 kg・並進だけの概算（関節空間の慣性・d ゲインは未考慮）。どちらも実機の測定値ではない

ハイブリッド位置/力制御

仮想仕事の原理：τ = JT F

  • つり合っていれば関節がする仮想仕事 = 手先がする仮想仕事
  • 手先に力 F を出したい → 必要な関節トルクは τ = JT F
  • 外力 Fext がわかれば −JT Fext を足して打ち消せる
  • 逆に関節トルクから手先の力：F = J−T τ（特異姿勢でなければ）

力を手先の方向（x, y, z）ごとに扱える → 次は制御則へ

位置も力も「手先の力」で書く

  • 位置制御：目標とのずれをばね・ダンパの力に変える（手先の PD 制御）
  • 力制御：目標の力を出しつつ、FTセンサで測った力との差を補正
  • どちらも出力は手先の力 F → 仮想仕事の原理 τ = JTF で関節へ
  • 同じ「手先の力」だから方向ごとに選んで足せる → 選び方が選択行列 S

選択行列 S：方向ごとに位置か力か

  • S：方向ごとに 0 = 位置制御、1 = 力制御
  • 指令 = (I − S) 位置制御 ＋ S 力制御
  • 関節へは τ = JT( … )（仮想仕事の原理）
  • 位置と力の方向が直交 → 干渉しない

位置制御ロボットでは手先の位置指令に S をかける
（位置/力ハイブリッド制御：Raibert & Craig, 1981）

位置と力をどう合成するか

  • 位置ループと力ループを並べて、誤差に S をかけて方向を振り分ける
  • F = (I − S) Fpos ＋ S Ffrc → τ = JTF（S = 0 の方向は位置、1 の方向は力だけが効く）
  • 位置制御ロボットでは力制御則の出力を位置指令の補正にする（UR の force_mode）

ハイブリッド位置/力制御の使われ方

  • 研磨：Z は力、XY は位置
  • 位置制御ロボット＋FTセンサでできる
  • 産業用でよく使う：研削・研磨・嵌合
  • UR：force_mode() で力の軸と目標を指定
  • ROS2：FZI の compliance controller で近い動き

フリードライブと接触作業の制御的な違い

M x″ + D x′ + K (x − xd) = Fext

  • 同じ式で、違いはばね K（と目標 xd）があるかだけ
  • 接触作業：目標を壁の少し奥に置くと、押し付け力 ≈ K (xd − x)
  • フリードライブの「重さ」＝仮想質量 M（動かしやすさ）
  • 「軸ロック」＝特定の方向をアドミッタンス計算から外す → XY 平面だけ動かせる
