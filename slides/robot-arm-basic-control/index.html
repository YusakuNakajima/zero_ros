ステップ③動作指令は2分類

PTP（Point To Point）
経路を規定しない・関節空間で補間
→ UR: movej()
CP（Continuous Path）
TCPの経路形状を規定・直交空間で補間
LIN 直線
→ movel()
CIRC 円弧
→ movec()

詳細は以下↓

PTPの詳細

  • 関節空間での補間（UR: movej）
  • 各関節が最も速く目標に到達するように動く(グラフ)
  • 手先の軌道は予測できない
  • 障害物がない環境で使用する動作モード

LINの詳細

  • CPの直線（UR: movel）
  • 手先が直線的に移動
  • 関節の可動範囲や特異点により動きに制限
  • 部品挿入や溶接で使用
  • PTPよりも時間がかかる

CIRCの詳細

  • CPの円弧（UR: movec）
  • 中間点を指定して円弧を描く
  • 障害物回避や滑らかな動作で使用
  • 角を持つ物体の加工などに有効
  • 3点（始点・中間点・終点）が必要

URScriptでの対応

分類関数位置の与え方
PTPmovej(q, a, v, t, r)関節角 [j0..j5]
LINmovel(pose, a, v, t, r)TCP姿勢 p[x,y,z,rx,ry,rz]
CIRCmovec(pose_via, pose_to, a, v, r)経由点＋終点のTCP姿勢
 

movej([0, -1.57, 1.57, 0, 1.57, 0], a=1.4, v=1.05)
movel(p[0.3, -0.2, 0.25, 0, 3.14, 0], a=1.2, v=0.25)
movec(p[0.35, -0.1, 0.25, 0, 3.14, 0],  # 経由点
      p[0.3, 0.0, 0.25, 0, 3.14, 0],    # 終点
      a=1.2, v=0.25)
  • 引数の型に「関節空間 / 直交空間」の違いがそのまま現れる

※ movej に pose を渡すと内部で逆運動学を解き、関節空間で補間します

URでブレンドを使うときの注意

  • 隣り合うブレンド円を重ねない
    • 重なると実行時エラー
    • 目安：r < 教示点間距離の半分
  • 最初と最後の点はブレンドできない
    • 停止状態から / への遷移になるため

補足：丸めずに連続で動けない？

  • 直線の角は位置は連続でも速度の向きが不連続（C⁰ だが C¹ でない）
  • 法線加速度 an = v² / ρ は角（ρ = 0）で発散
  • 角で選べるのは2つだけ
    • v = 0：止まる（r = 0）→ 時間を失う
    • ρ > 0：丸める（r > 0）→ 形を失う

丸めるのは妥協ではなく、角を止まらずに通る唯一の方法

補足：ブレンド半径は精度と速度の交換レート

vmax = √( amax · r )

許容加速度 amaxブレンド半径 rコーナー通過速度の上限
2 m/s²50 mm0.32 m/s
2 m/s²10 mm0.14 m/s
  • r を小さくすると経路は正確になるが、コーナーで自動的に減速する
  • 「ブレンド半径を小さくしたら遅くなった」の答えはこの式

※ 90°コーナーを半径 r の円弧で丸めた場合。一般には r ではなく曲率半径 ρ で vmax = √(amax · ρ)

補足：丸めない連続パスはある？

  • 教示点を通るスプライン（KUKA の SPL、CNC の NURBS 補間など）でも、折れ線の角は通らない
  • 違うのは誤差の置き場所だけ
方式教示点そのもの教示点を結ぶ折れ線
停止点通る一致する（ただし止まる）
ブレンド通らない（手前で丸める）コーナー付近でずれる
スプライン通る点と点の間でずれる

「誤差ゼロで滑らか」は存在せず、どちらのずれを許すかの設計判断

補足：振動はどこから来る？

  • 円弧ブレンドは向きは連続（C¹）だが曲率が不連続（C² でない）
  • 円弧に入る瞬間 an が 0 → v²/r に跳ぶ → ジャーク ∞ → 構造を揺らして残留振動
  • 上位の制御器はクロソイド・5次多項式・Bスプラインで曲率も連続にする
  1. 角を速度 > 0 で通れない（幾何）
  2. 関節トルク・加速度に上限がある（アクチュエータ）
  3. 停止を挟むとサイクルタイムが伸びる（生産性）
  4. 加速度の急変が振動を励起する（構造）
  5. 振動と停止が加工品質を落とす（プロセス）

「振動するから丸める」は因果が逆。丸め方が粗いと振動する

補足：現場でブレンドが必須な理由

なぜ必要か

  • サイクルタイム：毎点で減速・加速・整定。ブレンドだけで2〜3割縮むことも
  • プロセス：塗布・溶接・塗装は速度一定が必要。止まれないから丸める
  • 機械寿命：減速機・ブレーキへの繰り返し荷重

なぜ「円弧」で「半径」指定か

  • 計算が軽い
  • ずれの上限が保証できる：TCPは教示点から r 以内
  • 「ワークから30mm離したいので r は20mmまで」と干渉を設計できる

プログラムから動かす(URの例)

Python ライブラリ ur_rtde で、前の URScript と同じ動作を書く

  • 関数の対応は同じ（moveJ / moveL）。違いは ①引数順が (speed, acceleration)、②ブレンドは経路で渡す、③moveC が無い

ロボットアームの精度について

  • 仕様書は絶対位置決め精度ではない！
  • ISO9283は同じ動作の繰り返し精度を測定する

位置がズレる原因↓

位置がズレる原因は3つ

① 設計と実機のズレ

  • リンク長の公差、原点オフセット
  • TCP・ベース設置の測定誤差

毎回同じだけずれる
→ 校正・ティーチングで吸収できる

② 時間変動

  • 暖機による熱ドリフト（0.05〜0.2 mm）
  • 経年でバックラッシュが増える

校正では取れない

③ 動作条件

  • 進入方向（バックラッシュ）
  • 速度、ペイロード、姿勢

同じ点でも指令の出し方で変わる

絶対誤差の大きさを決めるのは①
実務で悩まされるのは②と③

質疑で聞かれたとき用: ・電源の OFF/ON では位置はずれない（アブソリュートエンコーダが位置を保持している）。 ・ずれるのはエンコーダのバックアップ電池切れやエンコーダ・モータ交換でマスタリング（原点情報）を失ったとき。これは保守イベントとして別扱い。

位置制御だけでは難しいタスク

  • 狭い場所に部品を入れる(例:Peg-in-holeタスク)などは位置制御だけだと難しい

どういった工夫があるのか↓

RCC(Remote Center Compliance)

  • 部品を嵌め合わせるなどの作業のずれを機械的に補償するツール
  • RCC自体はコンプライアンス制御に置き換わっている印象だが、柔らかい部品で緩衝する考えは治具づくりで有用

コンプライアンス制御

  • ばねのような制御をセンサでソフトウェア的に実現
  • 手先のフォーストルクセンサを使う場合と使わない場合があります

フォース制御

  • 任意の軸だけ一定の力をかける制御
  • 手先にフォーストルクセンサが必要です

フォース制御とコンプライアンス制御の違い

  • フォース制御 → 一定の力をかける
  • コンプライアンス制御 → ばねのように柔らか

ROSを動作生成で使う利点

ROS生成モーション

  • PC上で完全に動作を計算してロボットに送る
  • 複雑な動作軌道を精密に制御したい場合

メーカー提供モーション

  • ロボットコントローラでモーションを計算する
  • 動作軌道がシンプルor軌道が厳密でなくてよい場合

ROSをシステム設計で使う利点

ROSのシステム

  • 分散・モジュール型なので並列で開発を進めやすい
  • 複雑なシステムを他社ロボットに移植しやすい
  • 対応センサやアクチュエータは何でも接続できるが、どう使うのかは自分次第

メーカー提供

  • 並列での開発は難しい場合が多い
  • 他社ロボットに移植不可だが、簡単な動作は問題にならない
  • メーカー提供品しか使えないが、GUIなどが整備されててすぐ使える
