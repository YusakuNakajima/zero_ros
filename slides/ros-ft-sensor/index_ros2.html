力を測るセンサは2種類

1か所で力3＋トルク3を測る

手先：ツールにかかる力を直接測る

ベース：ロボット全体にかかる力を測る

各関節に内蔵、1軸ずつトルクを測る

ヤコビ行列で手先の力を推定

アームのどこが触れても気づける

例：Franka, KUKA LBR iiwa

→ 本スライドでは ① 6軸FTセンサ を扱います（センサなしの方法などは次の章のコラムで →）

コラム従来法：関節トルクセンサ

  • ハーモニックドライブは摩擦が大きく電流では外力が見えない → 出力側にトルクセンサ
  • 代表例：Franka・KUKA LBR iiwa（DLR の軽量アームの系譜）
  • 課題①：関節ごとにセンサが必要 → 高い・配線や部品が増える
  • 課題②：センサは「ひずむ」ことで測る → 関節の剛性が下がる
  • 課題③：ハーモニックドライブなど高価な特殊減速機が前提

コラム最近の手法：電流で推定

τ ≈ N · Kt · i − 摩擦　（Kt：トルク定数、N：減速比）

  • モータのトルクは電流にほぼ比例 → 追加センサ不要で安い・壊れにくい
  • 外力 ＝ 電流から出したトルク − 動力学モデル（重力・慣性）の分
  • 弱点：摩擦とモデルの誤差がそのまま力の誤差になる

コラム産業用ロボットと QDD の違い

  • 高減速ギアは摩擦・ヒステリシスが大きく、外力が電流に出にくい（衝突検知どまり）
  • QDD は大径モータ＋1段ギアで逆駆動できる → 外力がそのまま電流に出る
  • トルクセンサも特殊減速機も不要 → 部品が大幅に少なく、誤差も小さい

コラムDD・QDD なら実用的

  • DD（ダイレクトドライブ）：減速機なし。摩擦が小さく、電流がほぼそのままトルク
  • QDD：大径モータ＋1段遊星ギア（〜10:1）。トルクを稼ぎつつ逆駆動できる
  • 低減速なら電流からのトルク推定で十分な精度が出る → 電流ベースの力制御が実用的に
  • MIT Cheetah（7.67:1）・Mini Cheetah（6:1）の設計が公開され、広く普及

P. M. Wensing et al., "Proprioceptive Actuator Design in the MIT Cheetah", IEEE T-RO 33(3), 2017 ／ B. Katz et al., "Mini Cheetah", ICRA 2019

コラム四足・ヒューマノイドの主流

  • 中国勢（Unitree など）の四足・ヒューマノイドは低減速の遊星ギア＋大径モータが多い
  • 関節トルクセンサを積むより安く・量産しやすい
  • SDK は関節ごとに 目標角 q・速度 dq・トルク τ・ゲイン Kp/Kd を送る形
    → 中身は電流ベースのトルク制御と考えられる
  • 返ってくる関節トルクも推定値（専用センサの記載なし）

本スライドの担当範囲

FTセンサ全般で使う次の3つを説明します

  • データの読み出し
  • ノイズ除去
  • 座標変換

6軸 = 力3つ + トルク3つ

  • 力 F：軸の向きに押す・引く ／ トルク T：軸まわりにねじる（右手の法則：親指＝軸、指＝正の向き）
  • ROS では geometry_msgs/WrenchStamped の force / torque
  • 向きの基準は header.frame_id のセンサ座標系 → 軸の向きは本体の刻印やデータシートで確認

ROS のメッセージ：WrenchStamped


# geometry_msgs/msg/WrenchStamped
header:
  stamp: {sec: 1728600000, nanosec: 120000000}
  frame_id: ft_sensor_link
wrench:
  force:  {x: 0.12, y: -0.05, z: -9.81}  # N
  torque: {x: 0.01, y: 0.02, z: 0.00}    # N·m
  • 力＋トルクの組 ＝ レンチ（wrench）
  • stamp：いつ測ったか（他のデータと時刻を合わせる）
  • frame_id：どこで測ったか（後の座標変換で使う）
  • 確認：ros2 topic echo /ft_sensor/wrench

取り付け位置は2通り

○ ツールにかかる力を直接測れる。どの作業でも使える

△ ツールの重さも測ってしまう（次↓）

○ ワークにかかる力を測る。アームの姿勢に影響されない

△ その治具の上の作業でしか使えない

ツールの重さも測ってしまう

  • 何も触れていなくても、姿勢が変わると読み値が変わる
  • 対策①：作業直前の姿勢でゼロ点リセット（姿勢があまり変わらない作業向け）
  • 対策②：ツールの質量・重心を登録して重力分を差し引く（重力補償）

ノイズ除去

全画面表示

  1. 何も触れずにデータを取る
  2. FFT で周波数成分を見る
    → 全体に広がるホワイトノイズと振動のピーク
  3. 使いたい力の変化より高い周波数をカット（ローパス）

「フィルタ ON/OFF」で効き目を比べる
カットオフを下げすぎると押した力への反応が遅れる（「押す」で確認）

Python でのフィルタ例


from scipy import signal

fs = 1000.0                          # サンプリング周波数 [Hz]
f, P = signal.welch(fz_idle, fs)     # 無負荷データの周波数成分を見る

b, a = signal.butter(2, 20, btype="low", fs=fs)  # 20 Hz ローパス
fz_offline = signal.filtfilt(b, a, fz)  # 記録データ：前後から掛けて遅れゼロ
fz_online = signal.lfilter(b, a, fz)    # リアルタイム：遅れが出る
  • カットオフは「無負荷のスペクトル」と「作業で必要な速さ」の間で決める
  • 移動平均も簡単なローパスの一種（ただし切れ味は悪い）

座標変換

  • TFを使って同次変換行列を取得
  • フォースはそのまま回転行列で座標変換をする
  • トルクは回転行列で座標変換したもの ＋ (旧位置 − 新位置) × 新力（外積）で変換する
  • センサ座標系からロボット座標系へ
  • tf2_geometryライブラリの活用
  • リアルタイム座標変換

測る点でトルクが変わる

TCP を横に押しただけでも、センサにはてこのトルクが出る

fT = R fS
τT = R τS + p × fT

R：S → T の回転
p：T から見た S の位置

力は回すだけ。トルクは回す＋ p × f

ROS2 では tf2 で変換


#include <tf2_geometry_msgs/tf2_geometry_msgs.hpp>

// センサ座標系（msg.header.frame_id）→ TCP座標系
auto tf = tf_buffer_->lookupTransform(
    "tcp_link", msg.header.frame_id, tf2::TimePointZero);

geometry_msgs::msg::WrenchStamped out;
tf2::doTransform(msg, out, tf);  // 回転 ＋ p × f まで計算してくれる
  • センサと TCP の位置関係は URDF に書いておけば TF で取れる
  • 自分で書くときは力だけ回して終わりにしない（トルクの p × f が抜ける）

※ ROS 2 Humble の tf2_geometry_msgs（C++）で p × f の項が入っていることを確認

まとめ

  • 6軸の力・トルクは WrenchStamped で扱う。取り付け位置とツールの重さに注意
  • データの読み出し：パッケージを入れてトピックを確認
  • ノイズ除去：無負荷データの周波数を見てローパス
  • 座標変換：トルクは測る点で変わる → tf2 で変換
