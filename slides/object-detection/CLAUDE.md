# 物体検出 ~ロボットが「何が・どこに」を知る~

応用編「Visionベース」の 2 本目（ランディングページでは通し番号 8、カメラ/デプスカメラの次、Visionフィードバック制御の前）。ピッキングもビジョンフィードバックも「物体を見つけた」が前提なので、その土台として物体検出を扱う。ROS 依存部分は 1 枚だけなので `index.html` 1 本のみ（ROS 2 前提）。

## スライド構成

1. **タイトル**
2. **ロボットと物体検出**（縦 3 枚）：カメラ → 物体検出 → 取りに行く／合わせに行く（ビジョンFB）／数える・調べるの図／分類・検出・セグメンテーションの比較図／箱の中心 (u, v) ＋ 深度 → カメラ座標 → ロボット座標（キャリブレーションはカメラのスライドへリンク）
3. **前処理**（縦 6 枚）：前処理が性能を決める（撮影 → 前処理 → モデル → 後処理の図、学習時の画像に近づける）／撮影条件（失敗例と対策の 2 カラム）／よく使う前処理の表（歪み補正・ROI・リサイズ・色変換・明るさ補正・平滑化・正規化）／インタラクティブアプリ `interactive_app/preprocessing_demo.html`／OpenCV のコード例（undistort・ROI・LAB で CLAHE・GaussianBlur・BGR→RGB）／ハマりどころ
4. **YOLO**（縦 6 枚）：2 段階型と 1 段階型の図／NMS の図／NMS 不要（YOLOv10 が導入、YOLO26 で標準化、CPU 推論最大 43% 高速は Ultralytics の発表値）／YOLO の歩み（2016〜2026 タイムライン）／Ultralytics のコード例と AGPL-3.0／オープンボキャブラリ（Grounding DINO・YOLO-World・YOLOE）との使い分け
5. **ROS で使う**：カメラ → 前処理 → YOLO（2D＋深度→3D）→ TF → MoveIt の図、yolo_ros（mgonzs13、YOLO26 対応、`ros2 launch yolo_bringup yolo.launch.py`）、Isaac ROS
6. **応用例：RoboCup@Home**（縦 3 枚）：競技の概要と「指示 → 検出 → 3D → 把持 → 渡す」の流れ／物は大会会場で発表される難しさ／Hibikino-Musashi@Home（3D スキャン → PyBullet で合成 50 万枚・2 時間以内・自動ラベル → YOLOv8＋TensorRT、Grounding DINO と使い分け、RoboCup 2024 DSPL 1 位、arXiv:2511.20180）
7. **まとめ**（最後の fragment で次のビジョンフィードバック制御へつなぐ）
8. **参考資料**

## インタラクティブアプリ

`preprocessing_demo.html`：合成シーンの「赤いコップ」を色のしきい値で検出する。撮影条件（暗さ・電球色の色かぶり・ノイズ）を悪くし、前処理（平滑化・グレーワールドのホワイトバランス・明るさの正規化・HSV 判定）で立て直す。検出器は固定で入力だけ変える。「暗い部屋＋電球色」プリセットでは前処理なしで誤検出、1 つだけでは不十分、平滑化＋WB＋HSV などの組み合わせで成功する（IoU と誤検出数を表示）。iframe 埋め込み時は見出しと注記を隠す。
