「制御」しているかどうか です。

Mock Hardware vs Gazebo

→ 全画面表示

Mock Hardware (ros2_control)

  • ros2_control Mock Hardwareは、実機を使わずにロボットの制御をテストするためのROS2標準機能です。
  • 物理演算（重力や摩擦など）は行いませんが、「コントローラからの指令を受け取り、動いたことにする」という振る舞いをシミュレートします。
  • MoveItなどの動作確認によく使われます。

【重要】前のスライドとの違い

前章：モデル表示

(joint_state_publisher_gui)

  • 手動でスライダーを動かす
  • ロボットは絵として表示されているだけ
  • 自律的に動く機能はない
  • 実機制御のプログラムは動かない
➡

本章：制御シミュレーション

(ros2_control Mock System)

  • コントローラが計算して指令を出す
  • MoveItやナビゲーションが実際に使える
  • 実機と同じプログラムで動く

Mock Hardware起動用Launch (Python)


def generate_launch_description():
    # ...必要なインポート記述...

    # 1. ros2_control (Mock) を含むURDFのロード
    # "use_mock_hardware:=true" をxacro引数に渡すのがポイント
    robot_description_content = Command(
        [PathJoinSubstitution([FindPackageShare("xacro"), "xacro"]), 
         " ", urdf_path, " ", "use_mock_hardware:=true"]
    )
    robot_description = {"robot_description": robot_description_content}

    # 2. コントローラマネージャ (ros2_control_node) の起動
    control_node = Node(
        package="controller_manager",
        executable="ros2_control_node",
        parameters=[robot_description, controller_config],
        output="screen",
    )

    # 3. 各コントローラのSpawner (起動用ノード)
    joint_state_broadcaster = Node(package="controller_manager", 
                                   executable="spawner", 
                                   arguments=["joint_state_broadcaster"])
    arm_controller = Node(package="controller_manager", 
                          executable="spawner", 
                          arguments=["joint_trajectory_controller"])

    # 4. RVizの起動
    rviz_node = Node(package="rviz2", executable="rviz2", 
                     arguments=["-d", rviz_config_path])

    return LaunchDescription([control_node, joint_state_broadcaster, 
                              arm_controller, rviz_node])

use_mock_hardware:=true : URDF内でMockプラグインを有効化します。

ros2_control_node : 仮想的な制御ループを回すメインプロセスです。

spawner : 必要なコントローラを動的にロードします。

実行結果の確認

  • 見た目: RViz上の表示はモデル表示と同じに見えます。
  • 動作: Motion Planningプラグイン（MoveIt）から「Plan & Execute」を押すと、計算された軌道に沿ってロボットが動きます。
  • トピック: /joint_states は joint_state_broadcaster から配信されます。

$ ros2 topic info /joint_states

Type: sensor_msgs/msg/JointState

Publisher count: 1 (joint_state_broadcaster)

※データフローの詳細は「ros2_control」の章で解説します。

Gazebo

  • Gazeboは、ROSで最も広く使われている3D物理シミュレータです。
  • Mock Hardwareとは異なり、重力、摩擦、衝突、センサデータ（カメラ・LiDAR）などを物理エンジンを用いて計算します。
  • 実機を動かす前の「最終確認」として不可欠なツールです。

【注意】Gazeboは2種類ある

実は現在、世代交代の過渡期であり2つの「Gazebo」が存在します。
ネットで検索する際は区別に注意が必要です。

Gazebo Classic

(通称: 旧Gazebo / Gazebo 11)

  • 長年使われてきたバージョン
  • 資料が豊富で安定している
  • コマンドは gazebo
  • 2025年にサポート終了予定

Gazebo (New)

(旧称: Ignition Gazebo)

  • 次世代のモダンなシミュレータ
  • 画像が綺麗で動作も軽量化
  • コマンドは gz sim
  • 今後の主流はこちら

Gazebo環境のセットアップ

  • ROS 2とGazeboを通信させるためのパッケージをインストールします

1. モダンなGazebo (推奨) の場合
本スライドではこっちを使います 


# ros_gz (ブリッジやシミュレータ本体を含むメタパッケージ)
sudo apt-get install ros-${ROS_DISTRO}-ros-gz

2. Gazebo Classic (旧) の場合 


# gazebo_ros_pkgs (Classic用の関連パッケージ)
sudo apt-get install ros-${ROS_DISTRO}-gazebo-ros-pkgs

Gazeboの起動確認

インストールが完了したら、gazeboを起動

Humble の場合

(Gazebo Fortress)


# コマンドは "ign" です
ign gazebo shapes.sdf

Jazzy の場合

(Gazebo Harmonic)


# コマンドは "gz" です
gz sim shapes.sdf

⚠️ 初回起動時の注意

初めて起動する際はモデルデータのダウンロードが行われるため、 画面が出るまでに数分間、真っ暗な状態が続くことがあります。 故障ではないのでそのまま待ってください。

ros2_controlとの連携

どちらのGazeboを使う場合でも、ros2_control経由で動かすという基本構成は変わりません。

切り替えの仕組み

  • Mock Hardware: 実機なし、物理演算なし
  • Gazebo Classic: gazebo_ros2_control プラグインを使用
  • Gazebo (New): gz_ros2_control プラグインを使用

※本講座では、環境構築の手軽さから Gazebo (New) を使用します。

[実践 1] URDFの修正

Gazeboで動かすには、ロボットの記述（URDF）に
「Gazebo用の設定」を追記する必要があります。

ros2_controlタグの書き換え

urdf/ros2_control.xacro


<hardware>
  <plugin>mock_components/GenericSystem</plugin>
</hardware>
▶

<hardware>
  <plugin>gz_ros2_control/GazeboSimSystem</plugin>
</hardware>

GazeboSimSystem というプラグインを指定することで、
「実在しないハードウェア」ではなく「Gazebo上のロボット」として認識されます。

Gazeboプラグインの追加

さらに、robot.urdf.xacroの末尾（</robot>の直前）に、
Gazebo側からROS 2制御を呼び出すためのタグを追加します。


<gazebo>
    <plugin filename="gz_ros2_control-system" 
            name="gz_ros2_control::GazeboSimROS2ControlPlugin">
        <parameters>
            $(find my_robot_description)/config/controllers.yaml
        </parameters>
    </plugin>
</gazebo>

⚠️ ハマるポイント
このタグがないと、ロボットは表示されますが「力が抜けたようにダラっとして動かない」状態になります。
コントローラマネージャが起動しないためです。

[実践 2] Launchファイルの作成

Gazeboを起動し、そこにロボットを登場させる（Spawn）
ためのLaunchファイルを作成します。

Gazebo起動とSpawn (Python)


# 1. Gazebo Sim の起動
gazebo = IncludeLaunchDescription(
    PythonLaunchDescriptionSource(
        [PathJoinSubstitution([FindPackageShare("ros_gz_sim"), 
         "launch", "gz_sim.launch.py"])]
    ),
    launch_arguments={"gz_args": "-r empty.sdf"}.items(),
)

# 2. ロボットのSpawn (出現させる)
spawn_entity = Node(
    package="ros_gz_sim", executable="create",
    arguments=[
        "-topic", "robot_description", # URDFを読み込む
        "-name", "my_robot",
        "-z", "0.1", # 地面へのめり込み防止
    ],
    output="screen",
)

# 3. ブリッジ (ROS2 <-> Gazebo 通信)
bridge = Node(
    package="ros_gz_bridge", executable="parameter_bridge",
    arguments=[
        # クロック(時間)の同期
        "/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock",
    ],
    output="screen",
)

※コントローラの起動部分はMockの時と同じなので省略しています

実行と確認

作成したLaunchファイルを実行します。


ros2 launch my_robot_description gazebo_sim.launch.py
  • Gazeboの画面が立ち上がり、ロボットが表示される
  • ターミナルに "Configured and activated" と表示
  • RVizのMoveItパネルで「Plan & Execute」をすると、
    Gazebo上のロボットも連動して動く

動かない場合：
「再生ボタン(▶)」が押されているか確認してください。
Gazeboは起動直後、一時停止状態の場合があります。

ROS 2とGazeboの通信

なぜ「ブリッジ」が必要なのか？
その仕組みとデータの流れを図解で理解します。

言葉の壁（ミドルウェアの違い）

ROS 2とGazeboは、裏側で使っている通信の仕組み（言語）が異なります。

ROS 2

通信方式: DDS

"Hello DDS!"
通じない... 🗣️ ❌ 👂

Gazebo

通信方式: Gz Transport

"Hello Gz!"

直接は会話できないため、翻訳機（ros_gz_bridge）が必要です。

データの流れ（ダイアグラム）

ROS 2 ノード
(Nav2 / MoveIt)
指令 (/cmd_vel) ➡ ⬅ センサ (/scan)
ros_gz_bridge
Twist 変換
ROS msg ➡ Gz msg
LaserScan 変換
Gz msg ➡ ROS msg
Gazebo
(物理・センサ演算)
➡ ロボットが動く 周囲を計測 ⬅

Launchファイルの引数の書き方

/topic_name@ros_type[gz_type
  • /topic_name : 通信したいトピック名
  • @ : ROS 2の型 を指定する区切り文字
  • ros_type : ROS側のメッセージ型
  • [ : Gazeboの型 を指定する区切り文字
  • gz_type : Gazebo側のメッセージ型

実際の記述例（関節の状態）

/joint_states@sensor_msgs/msg/JointState[gz.msgs.Model

【重要】シミュレーション時間の同期

物理シミュレーションでは、計算負荷によって「時間の進む速さ」が現実と異なります。

/clock トピックの役割

Gazeboが進めている「シミュレーション内の現在時刻」をROS 2側に配信します。

ROS 2ノードはこれを受け取り、「今は現実時間の何時か？」ではなく「シミュレーション世界の何秒目か？」を基準に動くようになります。
(パラメータ use_sim_time:=True が必要な理由です)

Gazeboでの環境（障害物）の構築

ロボットを何もない空間（Empty World）ではなく、
障害物や壁がある環境で動かす方法を学びます。

環境を作る2つの方法

A. GUIで配置

  • 画面上でドラッグ＆ドロップ
  • 直感的で簡単
  • 一時的なテスト向き

B. Worldファイル

  • コード（SDF）で記述
  • 毎回同じ環境を再現できる
  • 本格的な開発・検証向き

A. GUIでの配置 (Gazebo Fuel)

Gazebo (New) には「Resource Browser」があり、
オンライン上のモデルライブラリ（Fuel）から物体を呼び出せます。

  1. 画面右側のタブから [Resource Browser] を開く
  2. 検索窓に「table」や「box」と入力
  3. 好きなモデルをメイン画面にドラッグ＆ドロップ

💡 Tips:
配置した環境は、左上のメニューから
File > Save World as... で保存（.sdfファイル）できます。

B. Worldファイルの作成 (SDF)

Launchファイルで empty.sdf の代わりに読み込ませる
オリジナルの世界ファイル（例: my_world.sdf）を作ります。


<sdf version="1.6">
  <world name="my_custom_world">
    <physics name="1ms" type="ignored">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1.0</real_time_factor>
    </physics>
    <plugin filename="gz-sim-physics-system" 
            name="gz::sim::systems::Physics"></plugin>

    <include>
      <uri>https://fuel.gazebosim.org/1.0/OpenRobotics/models/Sun</uri>
    </include>
    <include>
      <uri>https://fuel.gazebosim.org/1.0/OpenRobotics/models/Ground Plane</uri>
    </include>

    <model name="box_obstacle">
      <pose>2.0 0 0.5 0 0 0</pose>
      <link name="box_link">
        <collision name="collision">
          <geometry><box><size>1 1 1</size></box></geometry>
        </collision>
        <visual name="visual">
          <geometry><box><size>1 1 1</size></box></geometry>
          <material><ambient>1 0 0 1</ambient></material>
        </visual>
      </link>
    </model>
  </world>
</sdf>

Launchファイルの変更

作ったWorldファイルを読み込むように変更します。


# launch/gazebo_sim.launch.py

gazebo = IncludeLaunchDescription(
    PythonLaunchDescriptionSource(
        [PathJoinSubstitution([FindPackageShare("ros_gz_sim"), 
         "launch", "gz_sim.launch.py"])]
    ),
    launch_arguments={
        # "empty.sdf" を自作ファイルに変更
        "gz_args": "-r " + os.path.join(
            get_package_share_directory('my_pkg'), 
            'worlds', 'my_world.sdf')
    }.items(),
)

※ worlds フォルダを setup.py でインストールする設定を忘れずに！

【重要】ロボットは障害物が見えるか？

Gazeboに障害物を置いただけでは、
ROS 2（Navigationなど）は障害物に気づきません。

必要なもの：センサー

ロボットが障害物を避けるためには、以下の流れが必要です。

  1. Gazebo上でLiDARやカメラをシミュレートする
  2. センサーデータをROSトピック（/scan等）として出す
  3. ROS側のNavigation Stackがそれを受け取ってマップを作る
